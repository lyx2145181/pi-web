# Subagent Web 交互控制台

## 定位与功能归属

Subagent Web 交互控制台属于 Pi Web“Agent 会话执行与扩展交互”能力的支撑与操作功能。它在不修改、不分叉 `pi-subagents` 的前提下，使用插件已经公开的结构化协议，为浏览器用户提供当前会话异步任务的观察、详情查看和运行控制，并聚合仍存活会话的活动状态。

本功能不改变 Pi Web 以父会话聊天为核心的价值路径。任务控制台负责运行期操作和近期状态，父聊天继续承载长期可读的关键请求、决策和最终结果。

- 范围状态：当前范围。
- 实现状态：已确认但未实现。
- 上层功能：Agent 会话执行与扩展交互。

## 背景

Pi Web 已能加载 `pi-subagents` 扩展、显示扩展 widget，并通过插件公共事件总线 RPC 判断会话是否仍拥有活动后台任务。但现有 Web 界面缺少结构化任务树、按需详情和直接控制入口，用户通常需要从工具调用文本或父 Agent 的自然语言反馈判断后台进度。

`pi-subagents` 已公开 `ping`、`status`、`steer`、`interrupt`、`stop`、`resume` RPC，以及面向 RPC Host 的有界 inspect 协议。Pi Web 应消费这些公共能力，而不是维护插件私有实现或建立第二套任务执行系统。

## 目标

- 在当前父会话中展示异步 subagent、并行任务、Workflow 和嵌套任务的结构化状态。
- 允许用户对公共协议能够精确寻址的异步任务执行 steer、follow-up、interrupt、stop 和 resume。
- 默认只展示轻量状态，用户展开任务后再按需加载有界详情。
- 在侧边栏聚合仍存活 Pi Web 会话拥有的活动任务，并支持跳转到所属会话。
- 对失败、等待关注、控制失败和完成等事件提供分级反馈。
- 在插件缺失、版本较旧、返回截断或能力不完整时安全降级。
- 保持任务状态、控制权限和会话归属由 `pi-subagents` 判定，Pi Web 只负责 Host 桥接和用户交互。

## 非目标

- 修改、分叉或随 Pi Web 发布一份私有 `pi-subagents`。
- 手动创建 subagent，或提供 Agent 配置管理。
- Mission、Schedule 和其他扩展注册的 external runs 管理。
- 用户直接认领或回复 `contact_supervisor` 请求。
- 为 subagent 建立永久任务账本或固定 30 天/7 天历史承诺。
- 扫描所有历史会话、启动所有 RPC wrapper，或跨父会话直接执行控制。
- 解析插件状态文本、终端输出或私有文件格式来补齐公共协议缺失字段。
- 对公共协议未提供稳定目标身份的前台任务承诺完整控制。

## 数据来源与职责边界

### 权威来源

- 当前会话任务状态、节点身份、可执行控制和控制结果以 `pi-subagents` 公共 RPC 返回为权威。
- 任务详情使用插件公开的 Host inspect 协议；Pi Web 不直接读取 `asyncDir`、status 文件、transcript 文件或结果归档。
- 父聊天是关键 supervisor 请求、用户决策和最终结果的长期可读来源。
- 全局任务列表是 Pi Web 对仍存活会话状态的有界派生投影，不是任务权威来源。

### Pi Web 职责

- 为每个已启动的 `AgentSessionWrapper` 建立有界、可释放的公共 RPC 客户端。
- 将插件返回投影为白名单浏览器 DTO，过滤文件路径、内部目录、原始错误对象和未登记字段。
- 维护当前会话状态、请求 generation、加载状态和控制中的临时 UI 状态。
- 聚合现有 wrapper 的活动任务；wrapper 被释放后，不继续声称掌握其运行状态。
- 根据 `ping/capabilities` 和每次操作回执决定 status/control 控件，不能仅根据插件名称或版本字符串推测能力。
- inspect 不属于当前 event-bus `ping/capabilities`；Pi Web 只能通过精确注册命令 `subagents-inspect-rpc` 的存在及其版本化相关回执确认可用性，并在 reload 后重新发现。

### `pi-subagents` 职责

- 校验会话归属、任务身份、生命周期状态和控制合法性。
- 执行 steer、interrupt、stop、resume 等控制并返回结构化结果或错误。
- 限制状态和 inspect 负载，声明截断、遗漏和协议能力。
- 维持 supervisor 请求、后台进程、结果投递和插件自身产物的生命周期。

## 任务范围与状态模型

### 异步任务

当前会话控制台覆盖公共 `asyncSnapshot` 中的：

- 单个异步 subagent；
- 并行任务及其步骤；
- Workflow 根任务和步骤；
- 公共快照深度范围内的嵌套 subagent。

生命周期状态按插件返回展示，当前已知状态包括：

- `queued`
- `running`
- `complete`
- `failed`
- `paused`
- `stopped`
- `rejected`

`needs_attention`、当前工具、最近活动时间、turn 数和 tool 数属于活动投影，不替代生命周期状态。未知状态必须以中性样式展示，不得自动映射为成功或失败。

### 前台任务

公共 Fleet 状态可用于展示前台任务的 Agent、角色、模型、effort、开始时间和 token 汇总，但 Fleet key 是不透明协调 key，不是控制目标 ID。

因此：

- 前台任务默认只读；
- 实时详细输出继续由现有聊天工具调用承担；
- 只有公共协议同时声明控制能力并返回可靠目标身份时，Pi Web 才能显示对应控制；
- 禁止从 Fleet key、文本或数组位置推导 run ID。

### 截断和遗漏

Pi Web 必须读取公共快照的 caps、omitted 和 byte-limit 信息：

- 截断时明确显示“仅展示部分任务/节点”；
- 不把未返回节点视为已结束；
- 不为补齐列表读取插件私有文件；
- 全局数量以公共协议提供的 total/omitted 为准，无法精确时使用“至少”语义。

## 信息架构

### 一个任务中心，两个入口

- 当前会话入口位于 `ExtensionStatusBar` 的紧凑状态区域，打开后自动过滤当前会话。
- 全局入口位于侧边栏，展示仍存活会话的活动任务数量、等待关注和失败提示。
- 两个入口打开同一套任务中心组件和详情组件，避免形成两套状态与控制逻辑。
- 桌面端使用与聊天并排的抽屉；移动端使用全屏 Sheet。

### 当前会话视图

- 按任务树展示根任务、步骤和嵌套节点。
- 默认展示状态、Agent/标签、耗时、活动摘要和可用操作。
- 详情首次展开时再请求 inspect；收起后停止高频详情刷新。
- inspect 结果被插件标记截断时，UI 必须展示截断状态，不承诺完整 transcript。

### 全局视图

- 只聚合 Pi Web 当前 registry 中仍存活 wrapper 的活动任务。
- 全局视图只负责观察、提醒和跳转，不直接执行跨会话控制。
- 用户选择任务后先切换到所属父会话，由该会话重新查询权威状态，再显示控制。
- 不因打开全局视图而创建历史会话 wrapper 或加载所有扩展。

### 聊天关键节点

聊天流只对以下已有消息或事件提供专用展示：

- subagent 启动；
- supervisor 请求；
- 失败、暂停或停止；
- 最终完成。

高频进度和完整 transcript 不持续写入聊天渲染链路。关键节点可以打开任务中心；如果对应任务已不在公共快照中，应显示“运行详情已不可用”，而不是恢复私有文件读取。

## 控制语义

### 直接控制与模型回合

以下操作直接调用插件公共 RPC，不触发主模型回合：

- 状态刷新和详情查看；
- steer；
- follow-up（使用插件公开的 steer mode）；
- interrupt；
- stop；
- resume。

需要结合父聊天理解、总结、重新规划或做产品判断的操作继续由用户在主聊天中交给父 Agent，不伪装成确定性的控制按钮。

### 控制可用性

- 控件是否可见由 capability、节点身份、运行类型和最近一次权威状态共同决定。
- 提交控制前重新确认当前会话和目标身份；服务端仍以插件最终校验为准。
- `stop` 只对插件接受的顶层活动异步任务开放。
- `resume` 必须提供非空 follow-up 消息；它创建新的恢复运行，不宣称恢复原操作系统进程。
- `stopped` 不显示 resume；其他终态是否可恢复以插件回执为准。
- Workflow、嵌套节点或旧插件不支持某项操作时隐藏按钮，不能发送已知无效请求。

### 浏览器命令隔离

- Subagent 状态、inspect 和控制必须使用独立的服务端命令面，不得复用 `AgentSessionWrapper.send("steer"|"follow_up")` 等父 Agent命令。
- 服务端写操作只允许 `steer`、`interrupt`、`stop` 和 `resume` 固定枚举；follow-up/auto 只能作为 steer mode。明确拒绝 `spawn`、管理操作、`dir`、未知 method 和额外字段。
- Subagent 状态和控制入口只使用已存活 wrapper，不得沿用通用 Agent POST 的缺失 wrapper 自动启动行为。
- 目标 ID、消息、请求体、并发数和请求速率必须在服务端设界，不能只依赖按钮禁用或插件下游校验。

### 并发、幂等和回执

- 每个目标同一类控制同一时间只允许一个浏览器请求处于处理中，服务端也必须执行同目标并发约束。
- 请求必须带当前会话和页面 generation；会话切换后的迟到响应不得更新新会话。
- 成功只表示插件返回的具体语义，例如 steer 已送达/已排队、stop 已请求；不能将“请求已接受”展示为“进程已停止”。
- 超时和网络中断显示“结果未知”，随后重新查询状态；不得本地强制写成终态。
- `not_found`、`invalid_state`、`unsupported_method` 和执行失败需要保留可区分的中文用户提示。

## Supervisor 边界

`contact_supervisor` 继续使用现有插件流程：请求被投递到精确父会话并触发父 Agent，父 Agent通过 `subagent_supervisor` 回复。

Pi Web 可以：

- 将 `subagent_supervisor_request` 自定义消息渲染成清晰的请求卡片；
- 展示请求类型、来源 Agent 和父会话内的处理提示；
- 在页面后台时对仍需关注的请求提供不含敏感正文的通知。

Pi Web 不可以：

- 截获或延迟插件的 `triggerTurn`；
- 提供“用户直接回复”“认领”“释放”“交给主 Agent”按钮；
- 声称解决了父 Agent与用户并发回复问题。

## 历史与数据生命周期

- Pi Web 不创建独立持久任务数据库。
- 当前会话近期任务使用插件公共快照实际返回的有界窗口；窗口大小由 caps 决定，不在产品层承诺固定数量。
- 全局近期状态只保留在现有 wrapper 生命周期或本次 Pi Web 进程的有界内存中，可以在 wrapper 释放、服务重启或插件清理后消失。
- 活动中和等待关注的任务只要 wrapper 仍存活就继续查询；Pi Web 现有后台工作探针仍负责避免过早回收拥有活动任务的会话。
- 父聊天中的关键节点和结果不因任务中心记录消失而删除。
- UI 不使用“保存 30 天”“永久历史”等措辞。

## 通知规则

| 事件 | 默认反馈 |
|---|---|
| 启动、普通进度、steer 已送达 | 更新任务中心，不弹通知 |
| 成功完成 | 更新徽标和聊天关键节点；当前会话保持安静 |
| 失败、意外暂停、控制失败 | Toast、任务中心警示、所属会话未读提示 |
| supervisor 请求或 `needs_attention` | 高优先级 Toast 和全局徽标，但处理仍归父 Agent |
| `progress_update` | 更新时间线，不要求用户处理 |

补充规则：

- 不自动切换会话，不自动打开任务抽屉。
- 相同任务的重复事件合并，相近成功完成事件批量显示。
- 页面不在前台时，可以在用户已授权的前提下发送浏览器通知；通知不包含完整任务、路径、代码或 supervisor 正文。
- 完成提示音复用现有声音开关，不新增独立 subagent 声音设置。

## 破坏性操作与恢复

- steer、follow-up 直接提交，不二次确认。
- resume 直接执行，但明确提示它会创建新的恢复运行。
- interrupt 在任务正在执行工具时要求确认，并说明已发生的副作用不会回滚。
- stop 始终二次确认，显示目标任务和所属会话，并明确：停止顶层后台任务、停止后不可 resume、文件修改不会自动回滚。
- 控制按钮在收到回执前进入处理中并禁用重复提交。
- 控制失败或结果未知时保留任务当前权威状态，不能通过前端乐观更新伪造终态。

## 兼容与降级

- 插件未安装或 RPC bridge 未 ready：隐藏任务中心入口，不显示故障占位。
- `ping` 不支持所需 status/control capability：仅显示公共协议能够证明的只读状态。
- 精确注册命令 `subagents-inspect-rpc` 缺失、冲突、回执不匹配或 emit/retract 失败：允许查看概要，不显示详情入口；不得将 inspect 可用性归因于 `ping`。
- 某个控制 method 不可用：隐藏对应按钮。
- 返回未知字段：忽略；返回未知协议版本：拒绝写操作并降级为不可用或只读。
- 旧插件、返回 malformed payload、超时或 extension reload 不得使 Agent 主聊天不可用。

## 安全与隐私边界

- 浏览器 DTO 使用白名单字段；不得转发 `asyncDir`、session file、artifact path、原始插件 details 或堆栈。
- inspect 公共回复声明不含路径时仍执行 DTO 校验，不能因信任插件而跳过服务端投影。
- 所有控制经所属 `AgentSessionWrapper` 的事件总线发出，禁止浏览器指定任意文件目录作为控制目标。
- 全局聚合只暴露 Pi Web 已授权会话的最小展示信息；跳转后重新执行会话级状态查询。
- 浏览器通知、日志和 Server-Timing 不包含任务正文、代码、路径、凭证或模型输出。
- 插件错误不得通过未经处理的原始字符串注入 HTML。

## 性能与资源边界

- 不轮询或启动所有历史会话；全局聚合只遍历现有 registry。
- 活动时采用事件驱动更新加有界对账，空闲和不可见页面降低或停止轮询。
- 状态请求、inspect 请求和控制请求分别设置超时、本地 waiter 取消和 generation guard；Host inspect 不支持插件端取消时，只能释放本地监听并忽略迟到回执，不得宣称已取消插件读取。
- 任务抽屉关闭时不维持 transcript 高频刷新。
- 聊天列表不订阅每个 subagent 的高频进度，避免增加主消息渲染压力。
- 客户端状态、服务端请求和全局近期投影都必须有条目、字节或生命周期边界。

## 验收标准

1. 安装兼容插件时，当前会话能展示异步单任务、并行、Workflow 和公共快照内的嵌套节点。
2. 用户可以对协议允许的目标执行 steer、follow-up、interrupt、stop 和 resume，并看到准确回执。
3. 详情只在展开后加载；截断、遗漏和详情不可用都有明确反馈。
4. 侧边栏能聚合现有活动 wrapper 的任务并跳转到父会话，不创建历史 wrapper。
5. 前台任务在没有公共目标身份时保持只读，不从不透明 key 推导控制 ID。
6. supervisor 请求继续由父 Agent处理，Pi Web 不延迟、不认领、不直接回复。
7. 插件缺失、旧版本、malformed payload、RPC 超时、extension reload 和会话快速切换均安全降级，不影响主聊天。
8. stop、工具执行中的 interrupt 和结果未知场景符合确认与重新对账规则。
9. 浏览器响应、日志和通知不泄露插件返回的内部路径或任务敏感正文。
10. Pi Web 重启后不承诺恢复任务中心近期记录，但父聊天中的关键结果保持可读。
11. 任务中心关闭或页面后台时不产生无界轮询、wrapper 创建、transcript 请求或主聊天重渲染。

## 当前实现

- Pi Web 已为每个 AgentSession 创建独立扩展事件总线。
- `lib/subagent-background-work.ts` 已通过 `pi-subagents` 公共 RPC `status` 查询活动后台工作，用于保护拥有活动任务的 wrapper 生命周期。
- Pi Web 已支持扩展 status/widget 和通用 custom message 渲染。

## 已确认但未实现

- 通用 subagent RPC Host 客户端和白名单浏览器 DTO。
- 当前会话任务中心、渐进式 inspect 和运行控制。
- 现有 wrapper 的全局活动任务聚合与跳转。
- subagent 专用关键节点、分级通知、安全确认和兼容降级界面。
