# Pi Web 交互加载性能优化计划

## 计划定位

本计划用于解决 Pi Web 在加载会话、切换项目/会话、加载文件树、切换文件标签和预览 Markdown 时出现的长时间等待与主线程忙碌问题，并作为跨会话实施、验证和交接依据。

功能归属以根目录 [`AGENTS.md`](../../AGENTS.md) 中的 [Architecture](../../AGENTS.md#architecture)、[File Map](../../AGENTS.md#file-map) 和 [Key Design Decisions & Traps](../../AGENTS.md#key-design-decisions--traps) 为准；本文件只定义实施顺序、代码影响、性能与回归门槛、完成证据，不替代现有功能契约。

本计划的首要约束是：**不得通过删除、隐藏、延迟失效或弱化现有功能来换取性能数据。** 会话完整性、文件实时同步、Git 状态、工作树能力、访问控制、跨平台路径语义和现有交互能力均必须保留。

## 当前焦点

- 对应功能：会话浏览与切换、项目与工作树切换、文件浏览与预览。
- 当前目标：消除会话全量扫描和重复文件加载对交互关键路径的阻塞，使缓存命中场景接近即时响应，并使冷扫描不再拖住无关请求。
- 已满足前置：已完成静态链路分析和真实环境基线测量，已定位全局会话扫描、开发模式重复副作用、文件 Viewer 重复请求及重复渲染等主要问题。
- 明确不处理：不借本计划重做整体 UI、不改变会话文件格式、不改变 Pi SDK 的公开语义、不移除 Source/Preview/Diff/Live Watch/Git 状态等能力。
- 停止并询问条件：实施需要改变 Pi 会话格式、降低访问控制、引入不可自动重建的持久状态、改变工作树身份规则，或无法同时满足正确性与性能门槛时，停止并重新确认方案。

## 实施基线

### 已确认的性能事实

以下数据来自本计划建立前的真实环境，只作为本轮性能基线，不作为所有部署环境的固定容量假设：

- `~/.pi/agent/sessions/` 中约有 1034 个物理 JSONL 文件，总大小约 1.2GB；SDK 列表返回约 215 个有效会话。
- `SessionManager.listAll()` 独立执行约 4.55 秒。
- 开发服务器中的强制 `GET /api/sessions?force=1` 实测约 12.8～14.2 秒。
- 全局会话扫描进行时，原本约 0.06 秒的 Worktrees 请求可被拖延到约 13 秒。
- 当前项目根目录读取约 0.02～0.06 秒，Git status 约 0.13 秒，Markdown 正文读取约 0.04～0.15 秒。
- 当前项目会话在服务端热路径下约 0.04～0.17 秒，说明目录和单文件磁盘读取不是三个加载区同时卡顿的主要原因。

### 已定位的代码链路

- 全量会话发现：`lib/session-reader.ts`、`app/api/sessions/route.ts`。
- Agent 完成后的列表失效：`lib/rpc-manager.ts`、`components/AppShell.tsx`、`components/SessionSidebar.tsx`。
- 会话详情完整解析：`app/api/sessions/[id]/route.ts`、`hooks/useAgentSession.ts`。
- 文件首次读取、Git diff 和 watcher 重复同步：`components/FileViewer.tsx`。
- 文件标签只保留轻量状态、切回后重新挂载：`components/AppShell.tsx`、`components/file-tab-state.ts`。
- 文件树、Git status、Worktrees 在 CWD 变化时并发加载：`components/FileExplorer.tsx`、`components/SessionSidebar.tsx`。

### 开始实施前必须复核

- 当前分支和工作区已有修改，避免覆盖用户未提交内容。
- 当前 SDK 版本中 `SessionManager.listAll()`、`SessionManager.open()` 和会话文件发现行为。
- 会话列表、运行态、文件 watcher、工作树和路径安全相关现有测试。
- 基线测量使用同一组数据规模，并分别记录开发模式和可控的生产运行环境结果。

## 不可退化的功能与正确性约束

### 会话能力

- 列表仍必须覆盖所有有效会话，而不是只显示最近会话或当前项目会话。
- 必须保留会话名称、首条消息、消息数、创建/修改时间、父子关系、项目分组、工作树分支、运行中和未读状态。
- 新建、发送、完成、重命名、删除、级联重挂父会话、Fork、会话内分支、URL 恢复和跨项目最后会话恢复必须保持现有语义。
- 外部 Pi 进程新增或修改会话后必须能够被检测；缓存不得造成永久不可见。
- 不得截断历史、减少消息内容或改变 `entryIds[]` 与消息的对应关系。

### 文件能力

- Source、Preview、Diff、自动 Markdown/HTML 预览、滚动与换行状态恢复必须保留。
- 图片、音频、PDF、DOCX、下载、Markdown 本地链接和图片、文件及行号引用必须保留。
- Live Watch 必须继续覆盖普通写入、原子替换、删除和重建；优化后不得丢失 watcher 建立与首次快照之间的变更。
- Git changed 状态和 Diff 入口不得被隐藏；可以延后 patch 计算，但必须保留可发现性和结果正确性。
- 文件上传、冲突处理、刷新和已展开目录行为必须保持正确。

### 项目、工作树与安全边界

- 工作树仍按稳定 `projectKey` 聚合，保留主工作树、链接工作树、已删除工作树回退和 dirty remove 确认语义。
- Windows 路径必须继续使用 `toNativePath()`、`samePath()` 和服务端解析后的工作树身份，不得退回字符串直接比较。
- 每次文件、Git 和工作树访问仍必须通过 allowed-root、真实路径和 session-reference 授权；缓存命中不得绕过授权检查。
- 符号链接、已删除文件、跨项目标签和 `sourceSessionId` 的现有安全边界不得弱化。

### 明确禁止的“伪优化”

- 不关闭 React Strict Mode 来掩盖不幂等副作用。
- 不取消会话、文件、Git、Diff、Watcher 或 Worktree 功能。
- 不减少会话扫描范围而让旧会话消失。
- 不用任意长 TTL 替代版本校验或精确失效。
- 不只缩短或隐藏 Loading 文案而不减少实际工作。
- 不把所有文件标签永久挂载，造成多个 watcher、重型 DOM 和无界内存占用。
- 不通过降低安全检查频率或复用未经授权的数据提高速度。

## 性能目标与测量口径

性能门槛在阶段 0 复测后允许按环境分层，但任何调整必须记录测量依据，不得因实现未达标而直接放宽。

| 场景 | 目标 | 功能正确性条件 |
|---|---|---|
| 已有索引的会话列表首屏 | 服务端 P95 ≤ 300ms | 返回完整有效列表和运行态合并结果 |
| 会话索引后台校验 | 不阻塞无关 API；无关轻请求额外延迟 P95 ≤ 200ms | 新增、修改、删除最终被发现 |
| 已缓存会话切换 | 可见正文 P95 ≤ 500ms | 消息、分支、状态和草稿绑定正确 |
| 首次打开普通文本/Markdown | 可见内容 P95 ≤ 500ms，不计开发模式首次编译 | Watcher 建立窗口不丢变更 |
| 切回已打开文件标签 | 缓存首帧 P95 ≤ 100ms，随后版本校验 | 不显示其他授权范围或旧版本为最终结果 |
| Worktrees 与根文件树热加载 | 各自 P95 ≤ 200ms | 项目身份、Git 状态和 allowed-root 正确 |
| 文本文件首次加载请求数 | 1 次有效快照读取、1 条 watcher；无重复完整 diff | 版本变化时允许一次受控补偿同步 |
| 开发模式首次挂载 | 不因 Strict Mode 产生第二次强制全局扫描 | 保持 Strict Mode 开启 |

统一记录：服务端总耗时、会话文件数量和字节数、扫描/解析/序列化时间、Git 子进程时间、响应字节数、浏览器请求数、首次可见内容时间和主线程长任务。

### 阶段 1：消除重复刷新、请求风暴和失控并发

目标：不改变数据来源和功能语义，先消除确定存在的重复扫描、无关刷新和不可取消的陈旧请求。

预计影响：

- `components/SessionSidebar.tsx`
- `components/AppShell.tsx`
- `lib/session-reader.ts`
- `lib/worktree.ts`
- 相关 route、缓存和竞态测试

实施内容：

1. 使 Sidebar 初始加载在 Strict Mode setup/cleanup/setup 下保持幂等，不因第二次 effect setup 自动升级为 `force=1`。
2. 区分“手工强制刷新”和“生命周期增量刷新”：手工刷新保留完整校验能力，Agent 完成、新建、命名、Fork 等事件不再无条件触发第二次全局强制扫描。
3. 修正 forced generation 逻辑，使并发 force 调用共享一次已确认的刷新，不因连续 invalidation 让前一轮扫描作废并再次启动。
4. 将 Worktrees 刷新依赖从通用 session `refreshKey` 中拆出，只在 CWD、worktree add/remove 或明确手工刷新时失效。
5. 为浏览器 fetch 增加 AbortController 和 generation guard；快速切换时终止旧文件树、Git、Worktrees、会话和恢复请求。
6. 为 `resolveProject`、`listWorktrees` 和相同 session-list generation 增加 in-flight 合并及合理并发上限。
7. 保留现有运行态轮询和 SSE 语义；只减少重复重活，不减少状态更新来源。

阶段门槛：

- 开发模式首次挂载只发生一次有效会话列表刷新。
- 多个后台会话连续完成时，全局扫描次数受控且无重复 generation 重启。
- 快速连续切换后，旧响应不能覆盖当前项目/会话，旧 Git 子进程和请求能够终止或被可靠合并。
- 所有会话、运行态和工作树回归测试通过。

完成记录（2026-08-22）：

- 提交或最终变更范围：尚未形成提交；Sidebar Strict Effects 幂等刷新、手工/生命周期刷新分流、会话/文件树/Git/Worktrees/工作区恢复请求取消与 generation guard、forced refresh 合并、项目和 Worktrees in-flight 合并及 Git 并发上限。
- 实际迁移：无。
- 验证：`npm test` 620 项通过；`node_modules/.bin/tsc --noEmit`、`npm run lint` 通过；并发 force、项目解析和 Worktrees 合并测试通过；浏览器基线中 `/api/sessions` 的 `forcedRefreshes` 为 0，重复 HTTP 调用由初始化和工作区恢复产生并共享服务端缓存/在途任务。
- 计划偏差：无。
- 下一阶段入口：从 watcher 版本握手和 Text Viewer 首次快照去重开始；禁止提前建立会话元数据索引。

### 阶段 2：优化文件 Viewer、标签缓存和实时同步

目标：首次加载只做必要工作，切回已打开标签时立即复用安全、可校验的内容，同时保持 Live Watch 零丢失窗口。

预计影响：

- `components/FileViewer.tsx`
- `components/file-tab-state.ts`
- `components/AppShell.tsx`
- `app/api/files/[...path]/route.ts`
- `app/api/git/diff/route.ts`、`lib/git-changes.ts`

实施内容：

1. 重构首次快照协议：先建立 watcher，再读取一次快照；`connected` 不再无条件重复 read/meta/diff/bust。
2. watcher `connected` 和 `change` 携带服务端文件版本信息，至少覆盖 mtime、ctime、size、inode 可用信息；如果快照期间版本变化，只触发一次受控补偿同步。
3. watcher 建立失败时回退到直接快照并继续有限重连，不能因去重导致文件完全不可读。
4. 对 change 事件使用短 trailing debounce、AbortController 和 in-flight 合并；连续保存只提交最新版本，仍保证最终版本一致。
5. 增加有字节上限和条目上限的文件 LRU，key 至少包含绝对路径、`sourceSessionId` 授权上下文和显示类型；缓存内容必须通过当前请求授权和版本复核后才能成为最终状态。
6. 文件 API 支持基于文件版本的 ETag/Last-Modified 和 304；授权检查必须先于缓存命中返回。
7. 根据扩展名直接选择 Markdown/HTML 默认 Preview，避免正文到达后先执行一次完整源码 Prism 高亮再切换预览。
8. Git Diff 分为“是否变化”和“获取完整 patch”两步：普通文件首屏只获取或复用轻量状态，用户进入 Diff 时再计算 patch；changed row 的 Diff 入口和状态标识保持可见。
9. Source/Diff 超大内容优先采用 memo、deferred render 和可视区域虚拟化；纯文本 fallback 只能作为高亮策略，不得截断、隐藏或禁止查看完整文件。
10. 图片、音频、PDF、DOCX 同样去除 connected 后无条件 bust；DOCX 转换结果按文件版本受控缓存，文件变化后精确失效。

阶段门槛：

- 普通文本首次加载只有一次有效快照读取和一条 watcher。
- 在 watcher 建立前后进行普通写入、原子替换、删除、重建，最终内容均正确且无丢失窗口。
- 切回已打开标签满足缓存首帧目标，随后版本校验不会闪回更旧内容。
- Source、Preview、Diff、媒体、DOCX、链接、下载、引用、滚动和换行状态全部回归通过。
- 访问未授权路径时，缓存存在与否均返回相同拒绝结果。

完成记录（2026-08-22）：

- 提交或最终变更范围：尚未形成提交；统一文件版本/条件请求协议、watcher-first 快照、文本与媒体请求去重、授权上下文文本 LRU、版本化 DOCX 转换 LRU、按需 Git patch、延迟源码渲染和浏览器文件切换基线。
- 实际迁移：无；缓存均为有界、可删除、可重建的进程或浏览器内派生状态。
- 验证：`npm test` 635 项通过；`node_modules/.bin/tsc --noEmit`、`npm run lint`、`git diff --check` 通过；普通写入、原子替换、删除、重建、缺失后创建、304 和撤销授权后缓存拒绝测试通过；真实 Chrome 连续 5 轮执行文件 A→B→A，每轮均只有 2 次正文读取和 3 条 watcher，第三次切回未重复读取正文。

### 阶段 3：建立增量会话元数据索引

目标：会话列表不再为生成摘要而重复读取全部历史 JSONL；启动和刷新只解析新增或实际变化的文件。

2. fingerprint 至少组合 size、mtime/ctime 和平台可用的文件身份；仅 fingerprint 变化、新增或缺失的文件重新解析。
3. 索引文件如需持久化，必须带 schema version、原子写入、用户私有权限、损坏自动重建和容量边界；不得写回或修改原始 JSONL。

### 阶段 5：优化文件树、Git 和 Worktrees 刷新

## 整体验收矩阵

### 会话

- 初始列表、手工刷新、后台刷新、外部新增/修改/删除。
- 新建、发送、Agent 完成、运行中、未读、自动命名。
- 重命名、删除、级联重挂父会话。
- Fork、会话内分支、完整历史、导出。
- URL restore、每项目最后会话恢复、快速跨项目切换。
- 大会话、损坏文件、旧格式、transient runtime session。

### 文件与 Git

- 普通文本 Source、Markdown/HTML Preview、Diff。
- 换行、滚动、标签切换、关闭/重新打开面板。
- Markdown 代码块、数学、Mermaid、本地链接和本地图片。
- 行号引用、文件引用、下载。
- 图片、音频、PDF、DOCX。
- 普通写入、连续保存、原子替换、删除、重建。
- modified、added、deleted、renamed、untracked、conflict 和 line stats。
- 上传、冲突、覆盖、跳过和刷新。

### 工作树与跨平台

- 主工作树、链接工作树、工作树创建与删除。
- dirty worktree 409 与 force 确认。
- 已删除工作树会话回退。
- repo 子目录身份。
- Windows 大小写、分隔符和 Git POSIX 路径转换。

### 安全

- allowed-root 正常授权与拒绝。
- session-reference 文件授权。
- 符号链接逃逸防护。
- 删除文件和不存在路径的授权。
- 缓存命中、304、索引恢复均不能绕过授权。
- 日志和 `Server-Timing` 不暴露用户消息、绝对敏感内容或凭证。

## 风险与控制

| 风险 | 控制 | 主要阶段 |
|---|---|---|
| 会话索引陈旧导致会话缺失 | fingerprint 校验、定向事件更新、周期校验、手工完整验证、SDK 对照测试 | 3 |
| watcher 去重后丢失建立窗口内变更 | watcher-first snapshot、版本握手、变化后单次补偿同步、原子替换测试 | 2 |
| 缓存泄露跨 session 或跨 root 内容 | 每次先授权、cache key 包含授权上下文、拒绝路径测试 | 2、3、4 |
| 缓存无界导致内存恶化 | 条目与总字节双上限、LRU 淘汰、超大条目策略和内存压测 | 2、4 |
| Git/Worktrees 短缓存显示旧状态 | 精确失效、短 TTL、手工刷新、变更测试 | 5 |
| 快速切换产生乱序和误发送 | AbortController、generation、动作绑定目标 session、未就绪禁用写操作 | 1、4 |
| 持久索引损坏或版本不兼容 | schema version、原子写、私有权限、失败自动重建、原始 JSONL 只读 | 3 |
| 后台扫描仍抢占 Node 主线程 | worker thread/独立执行上下文、并发上限、无关 API 延迟门槛 | 3 |
| 开发模式看似改善但生产无收益 | dev/prod 分开测量，冷/热路径分开报告 | 0、6 |
| 优化破坏 Windows/工作树身份 | 复用 `samePath()`、`toNativePath()`、`projectKey`，执行跨平台测试 | 5、6 |
| 为达标偷偷减少历史或功能 | 不可退化清单和完整功能验收矩阵作为阶段硬门槛 | 全阶段 |

## 回滚与交付策略

- 每个阶段独立提交、独立验证，不把会话索引、Viewer 缓存和 Git 缓存混成一次大改。
- 新缓存和索引必须可关闭、可清空、可自动重建；关闭后回到正确但较慢的原路径。
- 回滚只允许回退优化实现，不回滚用户会话、工作树或文件内容。
- 任一阶段发现数据遗漏、授权差异、Watcher 丢事件、会话串线或跨平台身份错误，立即停止后续阶段并回退该阶段。
- 性能未达标但正确性通过时，保留测量证据继续定位，不通过移除功能或放宽一致性门槛交付。

## 交接记录规则

每阶段完成后才追加完成记录，内容仅包括：

- 完成日期和提交或最终变更范围。
- 实际新增缓存/索引版本及迁移情况；没有迁移时明确写“无”。
- 实际验证命令、性能数据和功能回归结果。
- 已确认的计划偏差及对应权威位置。
- 下一阶段入口和禁止提前处理的范围。

不记录临时报错流水账、未确认猜测和短期分支状态。实现改变长期契约时，先更新对应权威位置，再更新本计划。
