# 上游 v0.9.3 更新吸收计划

## 定位与证据基线

本计划在现有个人定制基础上评估并分批吸收上游 `v0.9.2..v0.9.3` 的增量；不是整版覆盖、发布安排或新的长期功能规范。历史 v0.9.2 吸收过程见 [04-上游更新吸收实施计划](04-上游更新吸收实施计划.md)；开发约束、分支流程与架构不变量以 [AGENTS.md](../../AGENTS.md) 为准，功能归属以 [规范索引](../specs/00-规范索引.md) 为准。

- 主要使用者：在 Pi Web 中切换项目、浏览会话、运行 Agent、配置模型和使用终端的用户。稳定入口是本工作树的 Pi Web 页面及其 `/api`，不是临时测试入口。
- 计划创建时：工作树分支 `0.9.2`，HEAD `d288762`，工作区干净；`package.json` 为 `0.9.2`，Pi SDK `0.87.0`、Next.js `16.3.5`。
- 上游来源：已获取 `v0.9.3` 标签（commit `0876cf4`）；相对 `v0.9.2` 有 11 条提交、29 个文件变化（含合并和发布提交）。这是一份已核对的上游快照；实施前仍须核对目标引用和当前工作区。
- Git 关系：当前分支手工吸收了 v0.9.2，`merge-base HEAD v0.9.3` 仍是 v0.9.1 的 `8366762`。**不得直接合并 `v0.9.3` 或整文件选择 ours/theirs**，否则会把已吸收的 v0.9.2 变化重新卷入大范围冲突。以 `git diff v0.9.2..v0.9.3` 和逐提交差异为移植来源。
- 当前可用证据：提交 `d288762` 的会话缓存修复已通过类型检查、lint 和全量测试（当时 1447 项）；**尚未在本轮验证浏览器中的 0.9.3 行为**，不以测试通过推断新版本已可用。

## 累计路径与保留边界

```text
启动本工作树 Pi Web
→ 登录或使用原有认证路径
→ 选择项目/工作树、打开会话和文件
→ 发送消息、接收事件、查看历史与终端
→ 在模型面板读取/编辑配置并获得明确的失败提示
```

各批次从同一入口增加可靠性，并保留前批结果；失败时用户不应看到静默丢配置、错误跳转、泄漏宿主密码或无解释的空白会话。

必须保留：项目/工作树聚合与过滤、置顶/折叠和纵向面板、定制主题和移动端交互；会话索引/分页/缓存指纹、请求取消/代次、聊天壳复用，以及 `d288762` 的 A→B→A 空白修复；精准工具/Skill、Subagent 开关、扩展生命周期、文件授权和 watcher/ETag。不因引入上游滚动条或列表优化删除本地功能、改写 Pi 会话格式或扩大文件访问权限。

最初范围外：推送、发布、PR、生产/共享配置迁移、修改用户真实 `models.json` 或凭证、无关重构。用户已明确要求先实现全部上游更新，包含“交互时才显示滚动条”的视觉变化；实际视觉和交互效果仍待用户自测。随后用户单独授权提交并通过 PR 合并至 `origin/ui-custom`，再更新主工作树并重启其 30141 服务；Git `main` 与 `upstream` 保持不变。发布和生产/共享配置迁移仍不在授权范围。认证、密码环境隔离已有此前请求的明确授权，额外扩展到 Skill 安装/更新子进程则已被用户排除；计划落档本身不授权其他安全改动。
