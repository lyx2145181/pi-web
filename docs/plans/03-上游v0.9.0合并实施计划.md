# 上游 v0.9.0 合并实施计划

## 计划定位

本计划记录个人分支同步上游 v0.9.0 的实施顺序、冲突决策、性能门槛与交接证据，不替代业务和架构权威规范。已确认优先级：**保留本地性能优化，尽量保留本地 UI 和操作习惯，同时尽量完整同步上游功能与修复。** 不以整文件选择 ours/theirs 代替语义合并。

功能归属与契约依据：

- [项目规范索引](../specs/00-规范索引.md)：会话组织、置顶排序及 Subagent 控制台的正式归属。
- [AGENTS.md](../../AGENTS.md)：会话、缓存、生命周期、项目身份、文件授权与开发约束。文件当前也有冲突，实施时结合双方版本及本轮已确认目标判断。
- [原性能优化计划](01-交互加载性能优化计划.md)：保留能力和原有测量方法的参考；历史测量不能替代本次基线。
- [Subagent 控制台规范](../specs/features/30-Subagent-Web交互控制台.md)：插件公共协议控制台的范围，不因引入上游内置执行器而自动替换。
- 上游 [Chat-only ADR](../adr/0002-chat-only-tool-selection.md) 与 [内置 Subagent ADR](../adr/0003-built-in-subagent-toggle.md)：待整合能力的契约依据，不能据此覆盖本地高优先级约束。

## 当前焦点与权限

- 当前目标：在现有工作树完成一次可验证的试合并，不发布、不自动提交。
- 用户已要求继续按计划推进；固定数据的核心浏览器测量已完成，阶段 1 已开始索引组局部合并。阶段 0 仍保留 Diff 单项基线待补；须在修改文件/Diff 实现前完成。每批写入前核实工作区并说明范围，高风险操作不因“继续”而自动获授权。
- 不执行 merge abort、reset、整文件覆盖或 push，不改写用户已有修改。用户随后明确要求“commit 然后继续”；当前索引仍有未解决合并项，不能部分提交。完成整次冲突处理和适用验证后按授权提交合并结果，不用 commit-tree、拆分历史或中止合并绕过该限制。
- 不修改真实会话文件、用户全局配置、凭证或通知订阅以准备测试。写入类测试使用隔离数据。
- CI、开发访问范围、部署与权限配置的实际修改，以及共享服务启停，按项目风险规则单独确认。既有暂存内容不等于本次已审查或获准发布。
- 不实施尚未交付的插件 Subagent 控制台；内置 Subagent 保留可选能力、默认关闭，不自动替代现有插件。
- 不为合并做无关重构，不为通过测试降低断言、隐藏功能或绕过授权。

## 验证与性能判定

稳定命令：`node_modules/.bin/tsc --noEmit`、`npm run lint`、`npm test`、`npm run perf:sessions`、`npm run perf:browser`。根据改动运行已有目标测试、`npm run test:e2e` 和 `npm run test:terminal`；执行前检查脚本是否创建会话、启动服务或写入产物，确保隔离。**禁止在开发 checkout 中运行 next build。**

性能必须与合并前 HEAD 在同环境、同数据、同模式和同操作下对照：

- 会话列表冷构建、热指纹复用的 P50/P95；解析数量和全量扫描次数。
- 普通与快速会话切换、历史加载的可用时间、API 请求数及传输量。
- 文件切换、缓存命中、Diff 探测、目录刷新耗时及重复读取/监听数量。
- 浏览器长任务、大列表滚动及拖拽稳定性；必要时观察内存和缓存上限。

冷热测量分开，重复采样并报告波动，不用单次最快值证明改善。新增终端/搜索等操作单独计量，不能掩盖普通聊天路径退化。请求数量、解析次数、授权与边界等可确定不变量必须保持；耗时若重复出现超出对照波动的退化，先定位并修复，不能任意放宽阈值。无法证明无退化时保持未通过/阻塞，不标记已完成。

行为反例至少包括：旧请求迟到、外部文件新增/删除、并发刷新、同会话换分支、压缩前消息分页、重复拼页、丢失父会话、后台探针失败、超时后显式关闭、watcher 断线与原子替换、缓存命中后的授权拒绝。

每阶段保留命令、结果摘要和临时证据路径；成功日志不整段写入文档。界面验收前用进程工作目录/启动信息证明实例加载本次代码，旧页面健康不算证据。
